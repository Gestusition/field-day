# AGENTS.md — backend (`apps/api`)

Go backend shared by web, mobile and NFC readers. Read the root `AGENTS.md`
first.

## Architecture: domain-based modular monolith

One binary, one database, strict module boundaries.

```
cmd/api/                 entrypoint: serve | migrate up | migrate down N | migrate version
internal/
  app/                   composition root: wires modules, router, MQTT (only place that sees all modules)
  apigen/                GENERATED from ../../api/openapi.yaml (oapi-codegen, strict server)
  platform/              shared technical building blocks, no business rules
    apperr/              typed client errors -> RFC 9457 problems
    auth/                OIDC (Casdoor) + device API keys, principal in context
    config/              env config (caarlos0/env)
    database/            pgx pool, embedded migrations, error helpers
    httpx/               contract middleware (route + auth + validation), problems, logging
    mqtt/                embedded MQTT broker for reader commands
    page/                cursor pagination over UUIDv7
    secret/              AES-GCM sealing, API keys, HMAC
  user/ credential/ reader/ access/ wallet/ audit/    <- domain modules
migrations/              SQL migrations (embedded into the binary)
```

Each domain module contains:

| File | Role |
|---|---|
| `queries.sql` | the module's SQL (input to sqlc) |
| `store/` | GENERATED by sqlc — do not edit |
| `service.go` | business rules; returns `*apperr.Error` for client errors |
| `handler.go` | implements its slice of `apigen.StrictServerInterface`; maps store <-> API types |

### Module rules

- A module only queries **its own tables** through its own `store`.
- Cross-module calls go through the other module's **service** methods, and
  the caller declares a small interface for what it needs (see
  `access.Credentials`, `wallet.Users`). Dependencies point one way:
  `access`, `wallet` -> `credential`, `user`. Never create cycles.
- `platform/*` never imports a domain module.
- `app` is the only package that imports every module.

## Request flow

`gin` -> request id / log / recover -> audit -> **contract middleware**
(find operation in the OpenAPI doc, apply its security scheme `userAuth` /
`adminAuth` / `deviceAuth`, validate params + body) -> generated strict
handler -> module handler -> service.

So handlers can assume the input matches the contract and the principal is
present (`auth.RequireUser(ctx)` / `auth.RequireDevice(ctx)`).

## Adding an endpoint

1. Edit `api/openapi.yaml` (repo root). Give it `operationId`, `tags`,
   `security` and the 4xx responses.
2. `make gen` — the build now fails until you implement the new method.
3. Add SQL to the module's `queries.sql`, `make gen` again.
4. Implement service logic + handler method.
5. Add/extend the integration test in `internal/app/app_integration_test.go`.

## Adding a migration

`make migrate-new name=add_something` creates the next numbered up/down pair.
Keep the `BEGIN; SET LOCAL lock_timeout ...; ... COMMIT;` wrapper. Use
`CREATE INDEX CONCURRENTLY` (in its own migration without the transaction
wrapper) for indexes on large existing tables. Squawk runs in CI.

## Conventions

- Errors: return `apperr.NotFound(...)` etc. for anything the client should
  see; return plain errors for bugs/infrastructure (logged, shown as 500).
- IDs are UUIDv7 generated by PostgreSQL (`uuidv7()`, PostgreSQL 18+).
- Money is `int64` minor units; never floats.
- Times are `timestamptz`; schedules are evaluated in `SITE_TIMEZONE`.
- Lists use cursor pagination (`page.New`, `page.Trim`) and return
  `next_cursor`.
- Logging: `slog`, structured keys, never log tokens, API keys, secrets or
  request bodies.

## Commands

```sh
make gen         # oapi-codegen + sqlc
make check-gen   # CI: fails if generated code is stale
make test        # go test -race ./... (integration tests need Docker)
make test-unit   # go test -short ./...
make lint        # golangci-lint
make dev         # live reload with air (needs .env)
```

Tool versions: Go from `go.mod`, oapi-codegen pinned via `go tool`, sqlc 1.31.x.
